# Floor mechanics parity

Reference: [Shattered Pixel Dungeon v4.0.2](https://github.com/00-Evan/shattered-pixel-dungeon/tree/v4.0.2), commit `57a4e06`. This is a rule-by-rule comparison for the floor subsystem, not a claim of seed parity.

| System | Reference entry points | Native implementation and remaining differences |
| --- | --- | --- |
| Initial population | `levels/RegularLevel.createMobs`, `actors/mobs/MobSpawner.getMobRotation` | Shuffled size-category weighted ordinary rooms (including the exit), an eight-cell entrance exclusion, eight floor-one spawns, and a 25% second-monster attempt. The native room occupancy cap was removed in v0.1.11alpha. LOS, painter vetoes and actor scheduling still differ. |
| Respawn | `MobSpawner.act`, `levels/Level.spawnMob`, `RegularLevel.randomRespawnCell` | Bounded random-room sampling, out of sight at least 12 connected steps away, ordinary-floor cooldown and a one-turn retry. A failed creation consumes its selected rotation entry as in the pinned implementation. Native room occupancy caps were removed. Original actor scheduling remains incomplete. |
| Floor events | `levels/Level.create`, `Dungeon`, each regional NPC's `Quest` | Supported feelings each occupy one of fourteen outcomes; regular-floor rules do not spill onto bosses. Chasms, trinket overrides, original quest-room injection, Old Mine and Imp Vault are not equivalent. Corpse dust uses quadratic power costs but the port still uses a generic wraith and port FOV. |
| Rooms | `RegularLevel.initRooms`, `rooms/standard`, `rooms/special/SpecialRoom`, `rooms/secret/SecretRoom`, `levels/builders` | Entrances, exits and ordinary rooms use the original depth-based catalogs, size budgets and geometry constraints. Native `LoopBuilder` and `FigureEightBuilder` handle the graph. Special, secret, quest and shop inputs still use the port's run plan or simplified geometry. Layouts larger than 64×64 are retried; boss floors and exhausted retries use the legacy layout. Pit chains, remaining crystal rooms, and individual secret rooms are missing. |
| Terrain | `RegularPainter`, `Patch`, `Maze`, region painters | Uses upstream patch and maze masks, six non-maze connector interior painters, and the ordinary Pillars, Segmented and Circle Wall painters. Adjacent chasm connectors open their shared edges; chasm tiles block movement but not sight. Falling, chasm floor feelings, other room interiors and placement rules, high grass, door hiding and standard-room merging are not yet synchronized. |
| Interactions and loot | `RegularLevel.createItems`, `randomDropCell`, `Dungeon.posNeeded`, `Dungeon.souNeeded`, `items/Generator`, room painters | Ordinary floor loot consumes alternating category decks across a run. Per-category item decks and artifacts remain incomplete. Iron, gold and crystal keys are separate on newly generated floors. |
| Traps | `RegularPainter.paintTraps`, regional trap tables | The port samples distinct available floor cells. Extra traps on trap floors are visible. Its six-type regional mix, graphics, and effects are a 3DS adaptation with a six-turn toxic cloud. Alarms now redirect monsters across the floor; mapping reveals traps and routes avoid visible traps. The complete upstream trap tables and effects remain outstanding. |

V11 adds strength, hunger, healing, regeneration, fractional action remainder and room weights while keeping the V9 header layout and V10 map trailer. V9/V10 still load; missing strength starts at10 and hunger at0. Old HP/enemies are retained. V9 files without spawn-room metadata cannot replenish ordinary monsters on the loaded floor. See [Wiki mechanics audit](wiki-mechanics-audit.md) for migration limits and outstanding mechanisms.

`bash tools/check-floor-layout.sh [path-to-upstream]` compiles the pinned v4.0.2 Java builders and terrain algorithms on the host. It compares 1,000 builder outputs with shared room descriptors, 500 patch masks and 100 maze masks. A separate oracle extracts the original room factories, budget methods and geometry methods and compares 2,000 ordinary-floor input lists (with the same initial RNG state, depth and Large flag), including room classes, size limits, sampled dimensions, door eligibility and final RNG state. This does not compare the incoming RNG state of a full game run, or the entire floor from the same run seed.

The same script also compares 1,800 isolated room paintings with the original v4.0.2 Java painter methods, using the same rectangle, ordered door coordinates, size category and RNG state. It checks the terrain and final RNG state, not shared-wall and door painting across multiple rooms.

The port checks whether the hero can reach loot and supply locations from the entrance through ordinary doors. Required supplies use any available reachable floor cell when ordinary rooms have no eligible space. If a chest would cut off part of the reachable area, the loot appears on the ground.

In Azahar, scene `87` checks 800 floors, including typed key budgets, stair reachability, and each floor's planned strength potions and upgrade scrolls. v0.1.11alpha passed these checks with 429 floors containing non-walkable chasms, zero legacy fallbacks on regular floors and zero invalid room weights. Scene `91` checks respawn retry and rotation. Scene `92` checks three locks, trap states and a V11 save round-trip including a chasm tile. Scene `98` previews a generated chasm connector. A full-floor comparison still needs the remaining inputs and painters, plus terrain, entity and event fixtures.
